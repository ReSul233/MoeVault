# MoeVault
本地优先的 ACG 收藏管理桌面应用：动漫/电影/剧集/游戏/漫画/书籍统一管理，Bangumi·豆瓣·萌娘·Steam·VNDB 跨源聚合
# MoeVault · 桌面版

一个在自己电脑上运行的「动漫 / 游戏 / 影视」个人资源库。
联网抓元数据 → 本地入库 → 多维度打分 → 记录追番补番 → 写观后感 → 统计与导出。

**它是一个独立软件**：双击图标就打开自己的窗口，没有地址栏、没有标签页，窗口标题栏和任务栏里显示的是它自己的图标。

---

## 一、怎么启动

双击 `MoeVault.exe`（或桌面上的「MoeVault」快捷方式）。

- 想放桌面：右键 `MoeVault.exe` → 发送到 → 桌面快捷方式；
  或双击 `tools\make_shortcut.bat` 让程序自己创建。
- 关窗口即退出程序。
- 程序会在解压目录旁自动生成 `data` 文件夹保存你的数据。

**开机自启**（可选）：按 `Win + R` 输入 `shell:startup`，把快捷方式拖进去。

---

## 二、你的数据在哪

| 内容 | 位置 |
|---|---|
| 数据库 | `MoeVault\data\library.db` |
| 封面缓存 | `MoeVault\data\covers\`（你选定/入库的封面） |
| 网络图片缓存 | `MoeVault\data\imgcache\`（列表里的远程封面，删掉会自动重下） |
| Markdown 导出 | `MoeVault\导出\` |
| **自动备份** | `MoeVault\数据备份\`（每天首次启动一份，保留最近 7 份） |
| 运行日志 | `MoeVault\logs\` |
| 程序配置 | `MoeVault\config\`（启动偏好 `prefs.json`、网络通道记忆 `netprefs.json`） |
| 窗口缓存 | `MoeVault\.webview2\`（WebView2 浏览器数据） |

**以上全部都在软件自己的文件夹里**，所以把整个 `MoeVault` 文件夹拷到别的机器（或 U 盘）
就能直接接着用，不需要重新配置；日志与配置也不会再散落在 C 盘用户目录。

备份 = 复制整个 `data` 文件夹。也可以在「设置」页导出 JSON 备份。
**程序还会自己备份**：每天第一次启动时把 `library.db`（连 `-wal`/`-shm`）快照到
`数据备份\`，保留最近 7 份自动轮换，设置页可看「上次备份时间」并手动「立即备份」；
启动时还会跑一次数据库完整性自检（有问题会在设置页标红）。
升级程序时 `tools\build_exe.bat` 会**自动备份并还原 `data`**，不用手动操心；
如果手动替换文件，只换 `MoeVault.exe` 与 `_internal` 即可，别动 `data`。
早先版本把日志与配置放在 `C:\Users\<你>\.acg-library\`，第一次启动新版时会**自动复制**过来
（原文件保留不动）—— 所以「窗口打开方案」与「跑通的网络通道」都不会丢。

> 注意：`ani-library\data` 是**源代码调试用**的数据库，跟这个独立程序不是同一份。
> 你录入的内容都在 `MoeVault\data` 里。之前浏览器版录入的记录已经帮你迁移过来了。

## 三、核心流程

1. **检索入库**：输入作品名 → 勾选数据源 → 点结果卡片 →
   **弹窗立刻开出来**（先用搜索结果里的基本信息撑着，字段区显示「正在抓取详细信息…」），
   详情抓回来只补封面 / 标题 / 简介 / 字段区，**你在这期间已经选好的状态、填好的时长不会被冲掉**。
   点「保存到资源库」即时入库 —— 封面下载在后台做，不用等（本地已有那张图时直接用本地的）。
   自动抓取的内容：封面 / 播出时间 / 制作公司 / 导演 / 音响监督 / 角色 CV / OP·ED / 完整 infobox。
2. **录入面板**（字段按类型变，见本节末尾的对照表）：
   - **动漫**：观看情况（想看 / 在看 / **看完** / 搁置 / **弃番**）、观看方式（追番 / 补番 / 重看）、
     **开始观看时间**、看完日期、**追至进度（话）**、是否看完、推荐追番 / 补番
   - **剧集**：同动漫一套（弃看），方式是追剧 / 补剧 / 重看，推荐字段是**推荐追剧 / 补剧**
   - **电影**：不记进度、**不记推荐**（电影没有「追 / 补」的概念），方式只有首看 / 重看
   - **游戏**：游玩状态（想玩 / 在玩 / **通关** / 搁置 / 弃坑）、游玩方式（首周目 / 二周目 / 多周目 / 白金）、
     **开始游玩时间**、通关日期、**游玩时长（小时）**、**完成度（%）**、是否玩完（**没有「追至进度」**）
   - **书籍**：**想读 / 在读 / 读完 / 搁置 / 弃读**，进度**完全按「章」记**：当前章 / 总章数（手动输入即可，百分比自动算；页数不再记录）
   - **影视**：电影不记进度，剧集按「集」；**漫画**按「话」
   - 收藏（★ 只看收藏）；**自定义封面**（抓不到封面时点「🖼 自定义封面」选本地图片）。
     标签与短板不再手填：标签直接用数据源抓回来的（详情页「标签」面板），短板留到导出后在
     Obsidian 里自己补
   - 面板里改「类型」，下面的字段会立刻换成那一套（已填的内容不会丢）
   - **完成日期是自动的**：状态一旦落到完成态（看完 / 读完 / 通关），程序会**自动补上完成日期**
     （自己已经填过的日期不会被覆盖）。面板里那枚「已看完 / 已通关」小开关和状态是同一件事 ——
     勾上它，状态下拉会跟着挪到完成态；取消就退回「在看 / 在玩 / 在读」。
   - **详情页头部的日期芯片，开始与完成各显示各的**：只填了开始日期就只显示「开始观看」，
     两个都没填就都不显示（绝不会拿开始日期或入库日期冒充「看完 / 读完日期」）。
3. **多维评分**：**维度按类型各是各的**。**每一项都按 10 分制打分**（不管你打的是哪个维度，
   0~10 分就对了），**总评由程序按权重自动算好**：总评 = Σ(得分 ÷ 10 × 权重)。
   - 各维度的权重**不挂在分数旁边**，统一写在打分面板「多维评分」下方的说明行里，用小数比例表示：
     - **动漫 8 个维度权重不同**：演出与制作、剧情与叙事 ×0.2，角色与表演、美术与视觉 ×0.15，
       音乐与声音、内核与共鸣 ×0.1，节奏与体验、完成度与稳定性 ×0.05（8 项全打 10 分 → 总评 10）
     - **游戏 / 书籍 / 影视 / 漫画各项权重相同**：总评就是各项的平均分（说明行一句带过）
   - 每个维度下面列的**子项**（如「演出与制作」下的 分镜 / 作画 / 调度 / 剪辑）只是评分参考，不强制逐项打分
   - **「＋ 自定义维度」是真的自定义**：输入名称即可新增，能打分、能删除、算进总评，且**存在本机**，
     刷新或重启后依然在（各类型各存各的）
   - **滑块拖动，也可以直接在小方框里输入数字**（支持一位小数）；面板右侧实时显示「总评 z（10 分制）」，
     z 就是各维度的加权平均分，跨类型可以直接比
   - 早先版本的动漫是「按各维度满分打分」（演出与制作 20 分制、节奏与体验 5 分制…），
     新版启动时会自动按比例折算成 10 分制并保留原值含义（20 分制里的 16 分 = 10 分制里的 8 分），
     **总评与排序一个字都不会变**
4. **观后感**：只留**「总体感受」**一项（观后感 / 读后感 / 玩后感都一样），失焦自动保存；
   想写长评可以写在里面，导出 Markdown 也会带上。
5. **详情页**：除评分与记录外，还有
   - 顶部把封面**虚化成背景**铺满整个头部，标题下方一排**关键指标小芯片**
     （游玩时长 / 评分 / 完成日期 / 入库时间，按类型自动换），扫一眼就知道这部是什么情况
   - **操作行收得干净**：只留「✎ 编辑评分与进度」一个主按钮，换封面 / 自动补封面 /
     补全 OP/ED·STAFF / 导出 Markdown / 删除都收在「⋯ 更多」菜单里（点空白处或 Esc 收起）
   - **其他信息**面板默认**只露 6 个高频字段**（中文名 / 原作 / 动画制作 / 音乐…），
     点「展开全部」才看完整原始字段（话数、放送星期、分镜、演出、原画…），不再一屏堆 30 多行
   - **长简介自动收起**（超过两百字），点「展开全文」再看；正文优先，界面清爽
   - **章节勾选**：集数区可在「列表 / 紧凑」之间切换 —— 列表里每一话带**话数 + 标题 + 首播日 + 勾选框**，
     点一行即标记看过，两种视图的状态实时同步；也可以「全部标记已看 / 已读」
   - **标签**面板、**SP / OP / ED 章节**、**角色与配音**（头像网格）、**STAFF**
   - 来源站 / 官网 / SteamDB 直达链接
   - 空封面不再是一块灰：按类型给**渐变底 + 类型图标**（动漫 / 游戏 / 电影 / 剧集 / 漫画 / 书籍各一色）
   - **同一系列**：标题前缀一致的作品（「咒术回战 死灭回游 前篇 / 后篇」）会自动串成一栏，
     横向小卡点一下就跳到那一部；不想并的可以点「移出系列」，程序会记住，下次启动不会又并回来
6. **本地搜索是全文检索**：顶部搜索框不只搜标题，还搜**别名 / 简介 / 标签 / STAFF 姓名与职位 /
   角色名与 CV / OP·ED 的曲名与词曲编曲** —— 搜「御所园翔太」「花江夏樹」「红莲华」都能直接命中作品。
7. **键盘快捷键**：`/` 聚焦搜索、`n` 手动添加、`b` 开关批量选择、`g` 去资源库、`h` 回首页、
   `Esc` 关弹窗 / 收起菜单、弹窗里 `Enter` 确认；资源库里**方向键在卡片网格中移动焦点、`Enter` 打开**；
   弹窗内 `Tab` 只在弹窗里循环（不会跑到背后的页面上）。
8. **首页**：启动直接落在首页，不再是一张空白搜索页 ——
   - 顶部一句概览（库里有多少部 / 正在追几部），右边是「随便看看」和「联网检索」两个入口
   - 三排横滑小卡：**继续**（在看 / 在玩 / 在读）、**最近收录**、**最近评分**；点任意一张进详情
   - 底部**随缘推荐**：随机挑一部优先挑「已经看完 / 通关」的，看不顺眼点「换一部」再摇一次
   - 库里还是空的时候，首页会直接告诉你该去检索还是从 AniList / Steam 导入清单
9. **批量操作与右键菜单**：
   - 资源库右上角点「批量」进入批量态，卡片左上角出现勾选角；选中后底部浮出一条操作栏 ——
     改状态 / 改类型 / **归入系列** / 导出 Markdown / 反选本页 / 删除 / 清空选择。
     改状态选项取**所选作品类型的并集**（混选动漫 + 游戏时「看完」和「通关」都会列出来）
   - 任意卡片**右键**都能唤起菜单：查看详情 / 编辑评分与进度 / 导出 Markdown / 加入（或取消）批量选择 /
     归入系列 / 粘贴链接入库 / 删除。点空白处、`Esc`、滚动或缩放窗口都会自动收起
10. **系列关联**：自动识别 + **手动归类**双轨 ——
    - **自动识别**：标题前缀一致的作品自动串成组（「咒术回战 死灭回游 前篇 / 后篇」），每次启动幂等重扫
    - **手动归类**：三个入口 —— 卡片右键「归入系列…」、详情页「⋯ 更多 → 归入系列…」、
      资源库批量勾选后点「归入系列」。对话框里**二选一**：并入库中已有的系列（自动、手动都行，单部也能归入），
      或者填个名字新建手动系列（**只选 1 部也能建** —— 先把「女神异闻录3」收进「女神异闻录系列」，
      以后再把 4 / 5 代并进来；多部时名字留空会自动取公共主名）
    - **移出**：详情页「同一系列」栏的「移出系列」。无论是从自动组还是手动组拆离，程序都会记住，
      下次启动自动识别不会再把它强行并回；想重新归组随时再走「归入系列」
    - **改名**：设置页「系列关联」卡里**每个系列都有「改名」按钮** —— 包括自动识别出来的。
      给自动系列改名（或往里归入别的作品）时，它会**自动转为手动系列**：成员与组名从此由你管理，
      以后的新续作不再自动进组（手动归入即可）。比如把「女神异闻录3」改成「女神异闻录系列」，
      再把 4 / 5 代归进去，就是你自己定义的系列了
    - 设置页还能一键「重新识别」（幂等，识别结果没变就不会重复写库）
11. **外部清单导入**：设置页「外部清单导入」卡，把别处攒的清单一次性搬进来 ——
    - **AniList**：公开接口，填用户名即可（动画 / 漫画清单都能导，含观看进度与状态，
      可选按 AniList 的评分回填第一维）；TV → 动漫、剧场版 → 电影、漫画里的 NOVEL → 书籍
    - **Steam**：需要一个免费的 Steam Web API Key 与 SteamID64（也可以直接粘个人资料链接，
      程序自己解析）；默认**只导玩过的**（喜加一不占库），时长换算成小时；勾「含未玩」才会把
      一点没碰过的也导进来（算「想玩」）
    - 导入按「标题 + 类型」去重（相似度 ≥ 0.90），库里已有的跳过，所以同一份清单导两次不会翻倍
12. **进行中 / 进度**：只列真正在追的（在看 / 在玩 / 在读）和还没开始的（想看 / 想玩 / 想读），
   **已看完 / 已通关 / 已弃坑的不再出现在这里**，去「我的资源库」看。
   进度**按类型各记各的**：动漫 / 剧集 / 漫画按「话 / 集」+1，**书籍按「＋1 章」**
   （当前章 / 总章数手动填，百分比自动算），**游戏按「＋1 小时」**（另可填完成度百分比），电影不记进度。
   **进度拉满会自动归为完成态**：动漫 / 剧集 / 漫画追到总集数 → 自动「看完」、书籍读到总章数 → 自动「读完」、
   游戏完成度到 100% → 自动「通关」，并自动补上读完 / 通关日期；你手动选的「搁置 / 弃」不会被覆盖。
   续作类番剧的章节编号是全系列绝对集数（如第二季从第 47 话起），**+1 按本季的相对话数走**，不会错位。
   **还没开始的作品点一次 ＋1 就等于开动了**：状态自动从「想看 / 想玩 / 想读」进入「在看 / 在玩 / 在读」，
   开始日期补今天，卡片从「待开始」挪到「进行中」——不会一点就从列表里消失。
   想手动改状态（改成搁置 / 弃）后再 ＋1，程序不会把它顶回去。
13. **关于与安全**：程序只监听 `127.0.0.1`，并做 **Host 头校验 + 访问令牌**（令牌随页面下发），
   别的网页即使能访问到端口也读不到你的数据；图片代理只允许公网 http(s) 地址（不会去探测内网）。
   设置页的「关于」卡能看到**版本号、构建日期、数据目录、窗口日志路径与更新日志**
   （版本号真源在后端 `app.py` 的 `APP_VERSION`，桌面壳跟随，不再两处各写一份）。
14. **设置页**只管配置（数据源自检 / 封面机制 / Bangumi / 反代 / 聚合 / 数据管理 / 备份 / 系列关联 / 外部清单导入 / 窗口与托盘 / 关于），
   **《使用说明》搬去了左侧栏的独立页**，不再把整篇说明书焊在设置页里。
   数据管理卡里能看到**封面缓存张数与占用**，可一键「清空封面缓存」（封面本体不受影响，下次浏览重抓）。
   封面机制卡里可以开关「**按类型统一封面裁切比例**」：开启后同类型的封面用同一比例（游戏按 Steam 的 2:3 竖版海报，
   其余 3:4），海报墙边线齐平；关掉则完整显示原图（比例差异大时会留边），保存后立刻生效不用刷新。
   首页的小卡**始终统一 3:4**，几种类型混在一排时高矮也一样。
   桌面版还有「**窗口与托盘**」卡，控制关窗是否留在托盘继续运行；**默认是关的 —— 点 × 就是退出**，不会留后台进程。
15. **统计**：顶部先按类型分档，切到哪档下面就只算哪档
   - **类型分段**：全部 / 动漫 / **影视** / 游戏 / 漫画 / 书籍 —— 哪一类有内容才亮哪一档，
     按钮右侧的小数字是该档的作品数；**「影视」= 电影 + 剧集的合计**。分段会写进地址
     （`#/stats/game`），刷新和浏览器前进后退都能保住当前档
   - **顶部四个指标卡**：作品总数（已完成 / 进行中）、已评分（占该档作品的百分比）、平均得分、
     累计游玩时长（该档没有时长记录时自动换成「已完成 + 完成度」），
     每个都带一个大号数值 + 指标名 + 浅灰补充说明，右上角配线性图标
   - **各类型概览**（只在「全部」档）：每种内容一格 —— 大号数量，加上平均分与「已完成 / 总游玩时长」，
     底部一条完成度进度条 + 右侧百分比；**点一格可直接跳到那一类的专项统计**
   - **数据洞察**：一句本地规则拼出来的总结（收录结构、平均分与最高分、时长去向），不联网、不调模型
   - **图表区两列堆叠**（左：评分分布 / 状态分布 / 时长排行；右：**通用维度统计卡** / 年度归档 / 时长分布），
     哪一块没数据就自动被后面的顶上来，不会留半格空白：
     - **评分分布**：纵向柱状图，每部作品的平均分四舍五入落到 1~10 分十档
     - **通用维度统计卡**（各分类档共用一套组件，右上角「统计维度」下拉实时切换）：
       - 可选维度：**类型分布 / 进度状态 / 评分区间 / 发行年份 / 题材TOP / 改编来源**；
         动漫、漫画、书籍档全 6 维可切，影视、游戏档 5 维（无改编来源）
       - **默认维度都是「类型分布」**，且保留各档原来的口径：全部 / 影视 = 作品类型占比，
         动漫 / 漫画 / 书籍 = **改编类型分布**（按 Bangumi 的 漫改 / 轻改 标签归类），
         游戏档 = **游戏平台分布**（多平台作品按平台计次，SteamDB 的「展开+」残渣自动去掉，
         Windows 归一为 PC）；切到别的档位再切回来，**每档记住自己上次选的维度**
       - **图表形态自动适配**：类型 / 状态 / 改编来源 → 环形图；评分区间 / 题材TOP → 横向条形图；
         发行年份 → 纵向柱状图（年份升序）。悬浮提示、数量、百分比、图例样式与旧图表完全一致，
         类型 / 状态 / 年份照样**点一下跳资源库筛选**
       - 没有数据时给友好的空状态占位；数据走独立接口 `/api/stats/dimension`
         （**缓存 5 分钟**，新增 / 编辑 / 删除作品后立即失效），切维度不卡顿
     - **年度归档**：纵向柱状图，按年份统计这一年完成/开始了多少部（年份取 完成日期 → 开始日期 → 入库时间）；
       **点某一年直接跳资源库筛那一年**
     - **状态分布**：横向柱状图，想看 / 在看 / 看完（游戏是 想玩 / 在玩 / 通关，书籍是 想读 / 在读 / 读完）各多少；**点一条筛资源库同状态**
     - **游戏时长排行**（有时长记录才有）：横向柱状图按小时从长到短，悬浮「时长 + 占比」，点柱子进游戏详情
     - **游玩时长分布**（只在游戏档）：把各游戏按 <10 / 10-50 / 50-100 / 100+ 小时分桶
   - **动漫档 KPI**：第四张卡是「**总观看集数**」（所有动漫的追番话数加总）
   - **我的高分榜**：「全部」档**按类型分开排**（每个类型各排各的，取前 5），
     切到单类型时就是那一类的 Top 10 —— 排名（前三金银铜）+ 海报缩略 + 迷你星级 + 分数，点一行进详情
   - **最近收录**：仅本档作品，最多 10 条，海报缩略 + 名称 + 来源 + 入库日期
   - **时间筛选**：右上角选年份后，KPI / 图表 / 高分榜整份重算（口径同年度归档）
   - 切档 / 切年份时整页淡入过渡；卡片悬浮轻微抬起加深阴影
16. **导出**：单个作品或全部导出为带 YAML frontmatter 的 Markdown（兼容 Obsidian 模板，
   含其他信息、标签、SP/OP/ED 段落），桌面版会**直接静默写入「导出」文件夹**，不弹下载框。
17. **我的资源库（海报墙）**：
   - 筛选栏：类型 / 状态 / **年份**（归档口径，与统计页联动）/ 排序 / 只看收藏
   - **分页**：一页固定 4 行卡片（行数按窗口宽度自动算列数），底部是上一页 / 页码 / 下一页；
     筛选条件一变就回到第 1 页。数据多了也不会一页拉到底
   - 统计页的图表（状态条 / 年份柱 / 类型饼图）点一下就会带着筛选条件跳到这里

### 界面配色与规范

界面是**深色影院主题**（参考 Jellyfin / Plex 那类媒体库软件的观感）：
底色 `#0f1117` 配三处极淡的径向光晕，侧栏、顶栏、卡片、弹窗都是**半透明毛玻璃**
（`backdrop-filter`），鼠标划过卡片会**轻微抬起 + 泛蓝紫光**，封面同时放大一点点。

- **主色是蓝紫渐变** `#818cf8 → #a78bfa`：主按钮、「联网检索」、进度条、统计页的
  KPI 大数字、详情页的大分数，全部是这条渐变，不再是单色。
- **类型色**全局统一：动漫=蓝 `#60a5fa`、游戏=紫 `#a78bfa`、电影=绿 `#34d399`、
  剧集=青 `#22d3ee`、漫画=琥珀 `#fbbf24`、书籍=玫红 `#fb7185`。
  卡片上的状态徽章、进度条、统计页图表全部取同一套色值。
- **文字只有三级灰阶**：主文字 `#e8eaf0` / 次要信息 `#9ba1b2` / 备注小字 `#6b7184`。
- 所有卡片圆角一致（14px），字号只用固定几档（11 / 12 / 13 / 14 / 15 / 18 / 26+），不临时插值。
- 滚动条改成**细的半透明**样式，不再抢视觉。
- 侧栏分「收集 / 回顾 / 系统」三组，图标是统一线宽的**线性 SVG**（不用 emoji，免得各系统渲染得五花八门）。
- 海报卡：状态徽章在封面左上角并按类型上色（深色玻璃底）、收藏★在右下角，
  评分改到标题下方用**迷你星级**表示，进度条颜色跟着类型走（动漫蓝、游戏紫…）。
- **详情页有 hero 背景**：把这张作品的封面模糊放大铺满头部，再叠一层深色渐变遮罩，
  所以每打开一部作品，头部色调都跟着那张封面走。没有封面时不加这层，不会出现灰带。
- 统计页与详情页的类型切换用**圆角分段按钮**（Vnite 那种），选中态是蓝紫渐变，
  右侧小数字是该档的作品数。

### 跨源聚合：一次搜索，一条完整记录

同一部作品在几个站点上的写法往往完全不一样 —— Steam 叫「千恋＊万花 体验版」、
Bangumi 叫「千恋＊万花」、VNDB 给的是中文名 + 日文原名、萌娘百科只补 OP/ED。
以前只能一次只入一个源，信息是碎的。现在搜索之后会自动做一件事：

**1）先认出「这是同一部作品」**

比对前会先把标题洗干净：全半角统一、大小写、繁简互通、去掉
「体验版 / 豪华版 / 合集 / 重制版 / Deluxe Edition」这类版本后缀，
再去比对标题相似度和发行年份（允许 **±1 年**容错）。
几条结果的所有标题变体（中文名 / 原名 / 别名）会两两比对，
所以 Steam 的英文名、Bangumi 的日文名、VNDB 的中文名能互相映射。

**2）按置信度决定要不要合**

- **高置信**（≥2 个不同源命中 + 标题高度一致 + 年份对得上）→ 合成**一张卡片**，
  卡片上标着「聚合自 N 个数据源」。
- **低置信**（只有单源命中，或者只是「有点像」——DLC、续集、同系列）→ **绝不合并**，
  仍旧各是各的卡片，你可以像以前一样单独入库。

> 这里的原则是**宁可漏合，不要错合**：错合会把两部作品的资料搅在一起，比不合并难受得多。
> 所以「艾尔登法环 黄金树幽影」「进击的巨人 第二季」这类只会被判成低置信，永远跟本体分开。

**3）点一下聚合卡 → 后台异步抓取**

点聚合卡片，程序会立刻返回（**接口不等网络**），然后在后台并发去拉各源的详情：

| 作品类型 | 主源（当骨架） | 谁只做补充 |
|---|---|---|
| 动漫 / 漫画 / 书籍 | **Bangumi** | 萌娘百科补 OP/ED，豆瓣补评分 |
| 游戏 | **VNDB**，其次 Bangumi | **Steam 只补价格、平台、好评率与商店信息** |
| 电影 / 剧集 | **豆瓣** | Bangumi 补角色与 STAFF |

- **主源打底，他源只填空缺**：主源已有的字段一律不覆盖，冲突全以主源为准。
- **评分各归各列**：Bangumi 分进 `Bangumi评分`、豆瓣分进 `豆瓣评分`、Steam 好评率进
  `Steam好评率`，互不覆盖。
- STAFF / 角色 / 歌曲 / 剧集按名称去重后合并（跟「补全 OP/ED·STAFF」同一套口径）。
- 完成后自动弹出预览表单，确认后才写进数据库。

**4）几个保护措施**

- **总耗时预算**：单次聚合任务默认最多 45 秒（`ACG_MERGE_TIMEOUT` 可调）；
  **单个数据源另算**，默认 15 秒没返回就判它超时跳过（`ACG_MERGE_SOURCE_TIMEOUT`）。
- **并发限流**：同一个聚合任务最多同时发 **3 个**数据源请求，不会一次性全捅出去。
- **单源失败就丢弃**：某个源连不上、超时、返回空数据，只把它自己剔掉并记进日志，
  其余源照常合并，**不会**让整个任务失败，更不会给接口报错。
- **同关键词节流**：90 秒内重复搜同一个词，直接复用已有任务，不会重复抓一轮。
- **已有作品不重复建**：库里已经有同一部作品时，**跳过完整聚合，只做增量补全** ——
  只往空着的字段里填，原有内容一个字不动，然后直接跳到那条记录。
- **随时可取消**：任务状态条上有点「取消」，取消后已拿到的结果一并丢弃。
- 程序关掉时后台任务自然作废（跑在守护线程里），不会卡住退出。
- **开关式兼容**：设置页最下面有「跨源聚合」一栏，可以整个关掉。关掉后搜索结果会退回
  「每个源各一张卡」的老样子，原有的搜索、单源入库、补全、导出、备份全部照旧。

任务状态会显示成「待合并 / 合并中 / 合并完成 / 合并失败」，
并逐个数据源列出「等待 / 抓取中 / 已取到 / 失败 / 超时」。
关键流程和异常都写进软件目录下的 `logs\merge.log`，排查问题时可以直接看。

### 各类型的字段不一样

同一个「记录」字段，不同类型的说法和取舍都不同（对齐你工作区里的那套 Obsidian 模板）：

| 类型 | 起止时间 | 记时长？ | 进度 | 状态词 | 方式 | 完成 |
|---|---|---|---|---|---|---|
| **动漫** | 开始观看时间 / 看完日期 | 不记 | 追至进度（话） | **想看·在看·看完·搁置·弃番** | 追番/补番/重看 | 已看完 |
| 剧集 | 开始观看时间 / 看完日期 | 不记 | 追至进度（集） | 想看·在看·看完·搁置·弃看 | 追剧/补剧/重看 | 已看完 |
| 电影 | 开始观看时间 / 看完日期 | 不记 | 不记进度 | 想看·在看·看完·搁置·弃看 | 首看/重看 | 已看完 |
| **游戏** | **开始游玩时间 / 通关日期** | **记：游玩时长（小时）+ 完成度 %** | 不记进度 | **想玩·在玩·通关·搁置·弃坑** | 首周目/二周目/多周目/白金 | 已通关 |
| 漫画 | 开始阅读时间 / 看完日期 | 不记 | 追至进度（话） | 想看·在看·看完·搁置·弃漫 | 追漫/补漫/重看 | 已读完 |
| **书籍** | 开始阅读时间 / 读完日期 | 不记 | 当前章 / 总章数（按章记，页数不记） | **想读·在读·读完·搁置·弃读** | 首读/重读 | 已读完 |

- **只有游戏记「时长」**，动漫/影视/漫画/书籍的表单里干脆不出现时长输入。
- **「全部状态」筛选只列当前所选类型自己的状态**：切到「动漫」就只出想看/在看/看完/搁置/弃番，
  不会混进游戏的「通关」或书籍的「读完」；面板里也会跟着类型换一套。
- 推荐字段也跟着类型走：动漫是推荐追番·推荐补番，剧集是**推荐追剧·推荐补剧**，漫画是推荐追漫·推荐补漫，
  **电影不记推荐**（电影没有「追 / 补」的概念），游戏与书籍也不记推荐。
- 导出 Markdown 的 frontmatter 同样按类型换字段名（游戏写「游玩状态 / 游玩时长 / 是否玩完 / 通关日期 / 完成度」，
  书籍写「阅读状态 / 阅读进度（章/总章）/ 总章数 / ISBN」，动漫写「观看情况 / 是否看完 / 追至进度 / 推荐追番…」）。
- 老库升级时状态词会自动换成本类型的新词（游戏/书籍的 已看 → 通关/读完，等等），**评分、进度、时间一个字都不动**；
  该类型的旧词在筛选下拉里仍然保留在末尾，老记录不会被静默改写。
- 在录入面板里改「类型」，字段区会立刻换成那一套，已经填好的内容会带过去。

### 选「书籍」为什么现在能搜到原著了（本轮修复）

以前不管选什么类型，豆瓣都只查**影视**建议接口，所以选「书籍」搜「教父」只会出电影，
原著永远搜不到。现在**搜索接口按类型分开**：

- 选 **书籍** → 走 `book.douban.com` 的图书建议接口，搜「教父」能出**原著小说**；
- 选 **影视 / 剧集 / 动漫 / 漫画** → 仍走 `movie.douban.com`，电影与剧集在详情里再细分。

入库后详情页会补上原著特有的字段：**作者、出版社、ISBN、总章数**，
导出 Markdown 时也会写进 frontmatter（`阅读进度（章/总章）`、`总章数`、`ISBN`）。

另外，**同名作品不会跨类型乱合**：电影《教父》与原著《教父》永远是两条独立记录，
游戏与同名剧集同理。程序在合并前会先判断「是不是同一类」，动漫/漫画同族、电影/剧集同族，
书籍、游戏各自独立 —— 宁可各存一条，也不把两种东西的资料搅在一起。

### 界面为什么变流畅了（本轮性能优化）

原来卡顿主要集中在「一次把整库渲染出来」和「一屏同时发几十个封面请求」两件事上。
这轮按影响大小逐项处理：

| 卡顿原因（按影响排序） | 处理方式 |
|---|---|
| 资源库一次把全部作品铺成海报墙，DOM 节点上千，滚动时重排/重绘很重 | **分页**：一页固定 4 行（列数按窗口宽度自动算），只渲染这一页 |
| 一屏几十张远程封面同时发起请求，图床还常常挂住 → 首屏白卡、滚动掉帧 | 封面**懒加载**：先只把地址挂在 `data-bg` 上，滚到附近（含上下 300px 预取）才真正取图 |
| 每次筛选/排序都整页 `innerHTML` 重画 | 只有列表区重画，筛选栏原地更新；筛选条件一变回到第 1 页 |
| 「总评」在列表里按维度逐条算，重复计算 | 一次批量算完（`score_map` 单次查询），列表直接取折算好的 10 分制总评 |
| 搜索每次输入都打网络 | 检索页只在**点按钮 / 回车**时发起；侧栏快速搜索才用 **400ms 防抖** |
| 统计页各接口串行等 | 启动与统计页的关键请求**并行**发起 |

**可测量的对比**（离线基准，`node tests/perf.mjs` 可复现）：

| 指标 | 优化前 | 优化后 |
|---|---|---|
| 构建 1000 张海报卡的 HTML | ~8.0 ms | 只建一页 24 张：**~0.16 ms**（约 50×） |
| 首屏 DOM 节点数（1000 部） | 11309 个 | **272 个**（约 2.4%） |
| 封面请求 | 首屏一次性几十个 | 滚到才发（懒加载） |
| 后端一次取一页（真实库，13 部） | — | `list_works` **0.4 ms** / `stats()` **0.5 ms** |

优化没有牺牲功能：分页、筛选、排序、封面、评分全部照旧，只是不再一次性全画出来。

### 再一轮：窗口与后端的性能修复（按性能工单逐项落实）

| 问题 | 修复 |
|---|---|
| **窗口被记忆在「无 GPU 兼容方案」，之后每次启动都卡** | 现在**每次启动都先探测硬件加速的方案 1**（9 秒内渲染成功就一直用它），失败才退回兼容方案；设置页新增 **「尝试启用硬件加速」** 按钮，点完重启软件即重新探测 |
| 兼容方案里连软件光栅都被禁掉 | 已从兼容参数中移除 `--disable-software-rasterizer`，兜底窗口也明显更流畅 |
| 无 GPU 时毛玻璃 / 大模糊 / 整卡位移动画开销巨大 | 兼容方案自动进入 **lite 性能模式**（URL `?lite=1`）：去掉全部毛玻璃与模糊、hover 不再位移缩放，观感几乎不变但滚动不掉帧 |
| 滚封面墙时多个抓图线程同时卡网络，数据接口被挤占 | 封面代理加**并发上限（3）**，超限直接回占位图绝不阻塞；加**进程内 LRU 缓存**（240 张）命中秒回；前端预取范围从 300px 收窄到 80px |
| 每个请求都重新应用一遍设置 | 设置应用加 **3 秒短缓存**（保存设置立即失效），图片并发时 CPU 占用下降 |
| 库大了列表 / 统计全表慢 | 列表排序与分页**下推 SQL**（2000 部压测：分页 3~5ms）；**统计结果缓存**（写入即失效，命中 1.4ms）；聚合补全先走标题精确 / 包含的 SQL 快路径 |
| 详情页每次点状态 / 勾集数都整页重建 | 改为**局部更新**：格子、计数、进度文案就地刷新，不再闪烁；进度页「＋1」只重画当前一张卡片，进度拉满自动归档时把卡片移出列表并提示 |
| `.webview2` 缓存无限膨胀拖慢启动 | 启动时自动清理缓存类子目录（Cache / Code Cache / GPUCache 等），**不碰** Cookie / LocalStorage 等登录数据 |
| 网络慢时重复搜索同一个词很磨人 | 搜索结果**本机缓存 24 小时**（同关键词直接秒回；某源出错的搜索不缓存） |

**2000 部压测数据**（真实算法，非估算）：`/api/works` 分页 **2.8~5.4ms**（验收线 50ms）、
`/api/stats` 命中缓存 **1.4ms**（验收线 200ms）、聚合标题匹配快路径 **1.5ms**。

### 网络通道是自动择优的（本轮重做）

你这台机器上几个站点的可达性差别极大，而且**坏通道的表现是「连接挂住不返回」**，
`urllib` 的 timeout 对这种卡死并不可靠 —— 这正是以前「搜半天没反应 / 总是获取不到」的根因。

现在所有数据源统一走一个**并发竞速**的网络层：对同一个目标同时发起「直连 / 系统代理 /
公共反代」多条通道，**谁先成功用谁**（不再一条条串着等），并且：

- 每个候选失败后自动补一枪（公共反代偶发 5xx / 抖动很常见）；
- 整个竞速有**硬性总时限**，坏通道不会把请求拖死；
- 记住的通道 **1.5 秒**内没动静就**自动升级为全网竞速**（本轮由 2.5 秒收紧到 1.5 秒，
  坏通道触发兜底更快）；
- 跑通的通道**记在本机**（软件目录 `config\netprefs.json`），下次冷启动直接走它，
  不再每次陪坏通道耗时间；它若失效会自动改选并覆盖记录。

实测（你这台机器）：bgm.tv 直连、系统代理都超时，只有公共反代能通 —— 现在首次搜索约 1 秒出结果
（以前要等 6~7 秒的无效探测）；Steam 官方接口时通时不通，走反代稳定约 1 秒；VNDB 直连约 1 秒。

#### 公共反代清单（本轮修正）

| 反代 | 拼接方式 | 状态 |
|---|---|---|
| `cors.isteed.cc` | 前缀（`https://cors.isteed.cc/<完整URL>`） | ✅ **主力通道**。实测 5/5 成功、约 0.7~0.9 秒，bgm 网页 / API（含 POST）、Steam 接口与搜索页全通，无需任何配置 |
| `corsproxy.io` | 查询参数（`?url=<编码后的完整URL>`） | ⚠️ 已取消匿名额度，不带 key 一律 `401`。想要这条备用通道，去 `console.corsproxy.io` 免费申请 key，填到设置页「公共反代通道」里即可启用 |
| ~~`api.allorigins.win`~~ | — | ❌ 已彻底失效（请求 10 秒无响应），**已从清单移除** |
| ~~`api.codetabs.com`~~ | — | ❌ 已彻底失效（请求 10 秒无响应），**已从清单移除** |

下次抓取时重新全网探测（换了线路 / 挂了代理之后用得上）。

### Bangumi 搜索为什么改用 v0 API 了

以前搜索和详情都抓网页。但 bgm.tv 的**搜索结果页是动态渲染的**，解析不稳；
而 v0 API 正好相反 —— 详情要 4~5 次请求且字段不全，**搜索却一个 POST 就全给了**。
所以本轮把两条路对调：

- **搜索** → `POST https://api.bgm.tv/v0/search/subjects`
  （`{"keyword": ..., "filter": {"type": [...]}, "limit": ...}`），一次拿到中文名、
  日文原名、日期、评分、封面；API 不可用或没结果时，自动退回抓搜索页 HTML 解析。
- **详情** → 仍以抓网页为主（一次请求拿全 OP/ED、完整 infobox、完整角色表）。

另外，**API 请求的 User-Agent 换成了「项目名 + 联系方式」**
（`ACG-Library/1.0 (MoeVault本地版; contact: ...)`），这是 Bangumi 官方的硬性要求 ——
用纯浏览器 UA 调 API 会被网关当成爬虫限流甚至直接拒绝。想换成你自己的邮箱或主页，
在设置页「Bangumi 设置 → API User-Agent」里填即可（留空就用内置标识）。
注意：**只有 API 用这个 UA，抓网页时仍用浏览器 UA**（网页本来就该像浏览器在访问）。

### 封面为什么常常抓不到（已修）

各站图床的规则完全不同，浏览器里直接引用 `<img>` 基本都会失败，所以现在封面统一由程序
取回、缓存在本机，再喂给界面（取回同样是并发竞速 + 硬时限，图床挂住也不会把流程拖死）：

| 图床 | 直接引用会怎样 | 现在的做法 |
|---|---|---|
| `lain.bgm.tv`（Bangumi） | 本机直连超时、走代理 502，**必然裂图** | 自动改走公共反代；列表用 400px 缩略图（11KB，比大图省 50 倍流量） |
| `t.vndb.org`（VNDB） | 直连建连后就挂住（永远读不回来） | 并发竞速各通道取回，实测走反代约 1.5 秒 |
| `*.doubanio.com`（豆瓣） | 不带 Referer 一律返回 **418 I'm a teapot** | 按域名补上 `Referer: https://movie.douban.com/` |
| `img.moegirl.org.cn` | 走系统代理会超时，且该站不提供条目封面 | 绕过代理直连；封面仍为空属正常，用 Bangumi 抓封面 |
| `cdn.cloudflare.steamstatic.com` | 正常 | 正常；游戏改用 600×900 **竖版海报**，铺满封面格不留黑边 |

- 取回的图片存在 `data\imgcache\`，同一条目第二次打开是**秒开**，断网也能看。
- **从萌娘百科入库的作品会自动补封面**：入库本身立刻返回，随后程序在后台拿标题去
  SteamDB / VNDB / Bangumi / 豆瓣搜一圈，谁先给可用封面就用谁的，补到后详情页自动刷新。
- 老记录（之前从萌娘入库、封面是空的那几条）在详情页点「🖼 自动补封面」即可救回来，
  也可以点「编辑」里的「🖼 自定义封面」手动选一张本地图片。
- 设置页「封面是怎么来的」面板可以看到缓存了多少张。

### Bangumi 打不开怎么办

程序默认就**并发竞速**：直连 `bgm.tv`、走系统代理、以及公共反代（主力 `cors.isteed.cc`）
同时发起，谁先成功用谁；跑通的通道会记住，后续请求直接走它。设置页「Bangumi 设置」里可以：

- **自动回退通道** —— 保持打开（默认）。允许走公共反代。
- **API User-Agent** —— 可换成你自己的邮箱或主页（Bangumi 官方要求 API 请求带上联系方式）。
- **Cookie** —— 在上面都失败时，登录 bgm.tv，从浏览器开发者工具里复制整条 Cookie 粘进来。
  填了 Cookie 后**不会**再走第三方中转。
- **测试 Bangumi** —— 立刻告诉你当前能不能用、走的是哪条通道。

### 关于 SteamDB

游戏库的来源就叫 **SteamDB**。程序**会真的去抓 steamdb.info**，抓到就用它的页面数据
（在「其他信息」里会写「数据来源：取自 SteamDB 页面」，并额外补上 SteamDB 的独有字段）。

> ⚠️ **明确告知：steamdb.info 在本机网络下抓不到，而且这是站点侧的硬限制，绕不过去。**
> 你用浏览器打开它也会先弹人机校验，程序拿不到那个校验结果。所以程序不会假装能抓，
> 而是直接把结论告诉你（设置页自检里会写「SteamDB 站点不可达：…」），并改用它的上游数据。

只是在你这台机器的网络上它抓不到，两个原因叠在一起：

1. **直连建连超时或立刻被拒** —— steamdb.info 挂在 Cloudflare 的 IP 上
   （`172.66.175.250` / `104.20.34.212` 等），本机直连 443 要么一直连不上，要么直接回 403。
2. **公共反代一律被挡** —— 换 `cors.isteed.cc` 等中转去抓，
   Cloudflare 统一回 **403 `cf-mitigated: challenge`**（人机校验），这是该站整站开启
   Bot Management 的结果，对着机器请求来的，跟我们怎么发请求无关。

所以**主路径直接用它的上游 —— Steam 官方商店接口**（现在不再每次查游戏都先白等一次 SteamDB）。
SteamDB 展示的数据本来就是从这几个接口抄过去的，字段一个不少：名称（中/英）、简介、发售日、
售价、玩家好评率、开发商/发行商、类型、平台、截图、Metacritic。约 0.6~1 秒出结果。

**Steam 搜索是双保险的**：

1. 先走 `store.steampowered.com/api/storesearch`（一步到位，带平台 / 售价 / Metascore）；
2. 若接口返回空列表（区域限制下很常见）或直接失败，**自动改抓 `store.steampowered.com/search/`
   搜索页 HTML**，从结果行 `<a class="search_result_row" data-ds-appid="…">` 里取 AppID、
   从 `span.title` 取标题，再补上发售日与售价。

程序仍会尝试 steamdb.info，但把「打不开」的结论**连时间戳一起记到本机，12 小时内不再重撞**，
所以不会拖慢任何一次查询。

每条游戏在详情页都会给「在 SteamDB 查看」和「Steam 商店」两个直达链接。

> 想手动再确认一次：设置页 数据源状态自检 →「重新检测」（强制重撞 SteamDB），
> 或「重置网络通道」（连通道记忆一起清掉）。
> 哪天你换了线路（比如挂了代理/VPN）能连上 SteamDB 了，程序会**自动改用它的页面数据**，
> 不需要改任何设置。

### 关于 VNDB（galgame 兜底）

参考 vnite 的做法新增了这个源。**Steam 只认英文名**，中文/日文名的视觉小说在 Steam 商店
搜不到（搜「千恋万花」只会得到 0 结果），VNDB 能直接命中，并给出：

- **官方简体 / 繁体中文标题**（没有中文标题时退回日文原名）；
- 开发商、发售日、VNDB 评分与投票人数、平台、平均时长；
- **内容标签**（已过滤剧透标签，按相关度排序）—— 正好填进「类型 / 标签」面板；
- 原始简介（已去掉 BBCode 标记）。

用的是 VNDB 官方的 Kana API（`api.vndb.org/kana`），公开、免 key、不需要注册，
本机可以直连。检索页把类型切到「游戏」时会自动勾上它。

## 五、窗口引擎说明（遇到打不开时看这里）

桌面窗口优先用 Windows 自带的 **WebView2**（Chromium 内核）。程序会按下面的顺序自动尝试，
全自动、无需你干预：

1. **常规模式** —— 正常启动 WebView2。
2. **兼容模式** —— 追加 `--no-sandbox --disable-gpu` 再试一次。
   部分电脑上安全软件 / 显卡驱动会拦掉 WebView2 的子进程（表现是窗口一片黑），
   这个模式能绕过去。程序会把成功的模式记下来，以后直接用它，不再重试。
3. **浏览器应用窗口** —— 万一 WebView2 完全不可用，自动改用 Edge / Chrome 的
   `--app` 窗口：同样没有地址栏和标签页，只是图标是浏览器的。

如果窗口打不开，看日志：软件目录下的 `logs\desktop.log`。
也可以在启动前设置环境变量 `ACG_ENGINE=browser` 强制使用第 3 种方式。

### 窗口与托盘（默认关窗即退出）

**默认行为：点右上角 × 或最小化到任务栏再关闭，程序都直接退出**，不留后台进程。

如果你希望关窗只是收进右下角托盘（比如批量补全、导入清单跑到一半不想被手滑关窗掐掉），

- **右键托盘图标** → 菜单：「显示主窗口 / 打开数据目录 / 退出」
- 随时可以把开关关回去，恢复「关窗即退出」
- 托盘建不起来（极少数环境）时会自动退回「关窗即退出」，不影响正常使用
